Current language models can produce self-contained single-file HTML games that work in a browser without a build step. No frameworks, no bundlers, no local server. The results are playable and illustrate clearly what the models have internalised about game loop structure, canvas rendering, and keyboard event handling.

Two examples: Tetris and a Bomberman clone.

## What they demonstrate

The models get the structural patterns right without prompting: the game loop (`requestAnimationFrame` or `setInterval`), input handling via `keydown` listeners, collision detection, and state management. The canvas API usage is correct. The Tetris piece rotation matrices are accurate.

What you will find if you look closely:
- **Edge case handling is incomplete.** Bomberman AI pathfinding works under normal conditions but can be tricked into infinite loops at certain wall configurations.
- **No mobile support.** Neither game has touch event handlers. Keyboard-only.
- **Performance is not tuned.** The rendering is correct but not optimal — no dirty-rectangle tracking, full canvas clears on every frame.

## The useful lesson

These outputs are useful as starting points, not finished products. The structural code — game loop, input dispatch, state machine — is correct and saves an hour of setup. The interesting game-specific logic (piece rotation, explosion radius, scoring) is also correct. The gaps are in edge cases and production quality.

For internal tooling, demos, or prototyping, a model-generated single-file HTML game is a reasonable first draft. For anything production-facing, treat it as scaffolding and expect to spend time on the corners.
