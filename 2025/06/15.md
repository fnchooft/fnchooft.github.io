DocBook XML is alive in many legacy systems with no migration planned. Before reaching for a full template engine — Jinja2, Mustache, M4 — it is worth knowing that `xmllint` can resolve XML entities at build time, giving you variable substitution with no extra dependencies and with proper XML validation built in.

Two patterns cover most use cases: co-located variables at the top of the file, and an external variables file shared across multiple documents.

## Pattern 1: co-located variables

Declare the variables as internal entities in the DOCTYPE, directly in the file you want to template:

<div class="snippet-tabs"
     data-tabs="config-co.xml.in|xml|config-co.xml.in,config-co.xml|xml|config-co.xml"
     data-github="2025/06/15"></div>

Expand with:

```bash
xmllint --noent config-co.xml.in --dropdtd > config-co.xml
```

The `--noent` flag resolves entities. `--dropdtd` removes the DOCTYPE declaration from the output so the result is clean XML with no processing instructions.

## Pattern 2: external entity file

When the same variables apply to several documents, extract them into a shared file:

<div class="snippet-tabs"
     data-tabs="vars.env|xml|vars.env,input-env.xml.in|xml|input-env.xml.in"
     data-github="2025/06/15"></div>

The template references the external file via `SYSTEM "vars.env"` in the DOCTYPE. Expand with:

```bash
xmllint --noent --loaddtd input-env.xml.in --dropdtd > input-env.xml
```

`--loaddtd` is required when the DOCTYPE references an external file.

## What you get for free

**Validation.** If a variable used in the template is not defined in the entity list, `xmllint` stops and reports the exact location:

```
input-env.xml.in:4: parser error : Entity 'PORT' not defined
        <address>http://&HOST;:&PORT;</address>
```

Compare this to `sed` substitutions, which silently leave unmatched patterns in the output.

**No extra tools.** `xmllint` is part of `libxml2`, present on virtually every Linux distribution. No pip install, no apt install beyond the base system package.

**The limitation.** Entity substitution is textual replacement — there are no conditionals, loops, or arithmetic. Once you need any of those, a real template engine is the right answer. For configuration files where variables are just strings injected into fixed structure, the entity approach is clean and maintainable.
