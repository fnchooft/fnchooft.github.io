Splitting source code for a retrieval-augmented generation pipeline is harder than it looks. A naive character-based splitter will cut across function boundaries, leaving fragment chunks that lack the context needed for a language model to answer questions about them. TreeSitter gives you a real concrete syntax tree for the code, which means you can split at semantically meaningful boundaries — module declarations, function definitions, clause groups.

LangChain's `RecursiveCharacterTextSplitter` has a `from_language` factory that uses TreeSitter under the hood for a growing set of languages. For Erlang and Elixir, which are not yet in LangChain's built-in language list, you can wire up the TreeSitter parser directly using the `tree-sitter-languages` package and integrate it yourself.

`ts_erlang.py` parses a sample Erlang module and prints the S-expression of the syntax tree. This is the diagnostic step — before writing a splitter, you need to know which node types the grammar uses for functions, clauses, and module attributes. For Erlang the relevant node types are `function_declaration` and `module_attribute`.

`text_split_erlang.py` and `text_split_elixir.py` show how to wrap the TreeSitter parser into a LangChain-compatible splitter. The chunks respect function boundaries: a function with multiple clauses stays together.

`app.py` is the complete pipeline: load source files from a directory, split them with the Erlang-aware splitter, embed with Ollama (`nomic-embed-text`), store in ChromaDB, and expose a `RetrievalQA` chain backed by a local LLM (`llama3.1`). The entire stack runs locally — no API keys, no external services.

`langchain-splitter.py` shows the alternative path using LangChain's built-in language support for languages it already knows about (Python, JavaScript, Go, etc.).

## Dependencies and forking

The `tree-sitter-languages` package bundles pre-compiled grammars for a large number of languages including Erlang. If you need a grammar that is not included, or need to modify the Erlang grammar, you can fork the `langchain-community` repository and patch the `LanguageParser` class directly:

```bash
git clone https://github.com/langchain-ai/langchain-community.git
cd langchain-community/libs/community
pip install -e .
```

The fork approach is necessary if you need the splitter to understand Erlang's multi-clause function grouping — the current built-in splitter treats each clause as an independent chunk, which loses context for pattern-matched functions.
