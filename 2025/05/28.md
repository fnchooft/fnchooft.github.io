The naive Erlang Fibonacci — two base cases, then `fib(N-1) + fib(N-2)` — is correct and immediately readable. It is also exponential in time and linear in stack depth. The idiomatic replacement is a tail-recursive iterator with two accumulators. This pattern appears constantly in Erlang code and is worth internalising.

## Why the naive version fails

```erlang
fib(0) -> 0;
fib(1) -> 1;
fib(N) -> fib(N-1) + fib(N-2).
```

Every call to `fib(N)` creates two stack frames, each of which creates two more. `fib(40)` requires over a billion recursive calls. No tail-call optimisation applies here — the recursive call is not in tail position because the addition happens after both calls return. The BEAM will not help you.

## The iterator version

The trick is to carry the current and next Fibonacci values as accumulator arguments, shifting the window forward by one position each step.

`Result` holds `fib(current)`, `Next` holds `fib(current+1)`. Each recursive call shifts: the old `Next` becomes the new `Result`, and `Result + Next` becomes the new `Next`. The counter decrements toward zero. When it hits zero the accumulated `Result` is the answer.

The recursive call is in the tail position — the BEAM replaces the current stack frame instead of pushing a new one. Stack depth is constant regardless of N.

## The pattern generalised

Any integer iteration that accumulates a result can follow this shape: a public entry point sets up the initial accumulators, and a private `_iter` function carries state forward until the termination clause matches.

For factorials the pair collapses to a single accumulator. For sequences that depend on more history, it grows — though at three or more accumulators a record or map usually reads better than positional arguments.
