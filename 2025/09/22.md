Network management code often needs to represent a list of interfaces where each interface can have a variable number of sub-interfaces and VLANs. In C, that means dynamic arrays — which means either `malloc`/`realloc` boilerplate or a library. [stb_ds](https://github.com/nothings/stb) by Sean Barrett is a single-header library that gives you dynamic arrays and hash maps with minimal ceremony.

This PoC models a simple network interface structure: named interfaces, each with a status enum, a description, and a dynamic array of sub-interfaces. A second example covers `stb_sprintf`, the companion formatting library.

`arrput(intf->subinterfaces, sub)` appends to the dynamic array and grows the backing buffer as needed. `arrlen(intf->subinterfaces)` returns the current element count. `arrfree(intf->subinterfaces)` releases the buffer and must be called when you are done — stb_ds does not use reference counting or destructors.

The `remove_subinterfaces_by_vlan` function illustrates the idiomatic stb_ds pattern for filtered removal: allocate a second array, copy elements that pass the predicate, free the original, and replace the pointer. There is no in-place removal.

## String formatting

`string_test.c` shows `stb_sprintf` in use. It matches the `printf` family interface exactly — `stbsp_sprintf`, `stbsp_snprintf` — and adds two extensions not in the C standard:

- `%b` — binary integer formatting.
- `%'d` — comma-separated integers (e.g., `1,000,000`).

Neither of these requires platform-specific code. Both are useful in logging and diagnostics contexts where you want readable output without pulling in a formatting library.

## What STB is and is not

The STB headers are single-file, public-domain C libraries. You copy the `.h` file into your project, define the `_IMPLEMENTATION` macro in exactly one `.c` file, and include the header everywhere else. There is no build system integration, no shared object, no versioning overhead.

The trade-off: no C++ compatibility guarantees, no thread safety on array operations, and the API is terse by design. For embedded or systems-level C where control over dependencies matters, stb_ds is a practical choice. For a larger codebase with existing container infrastructure it is probably not worth the integration.
