Network equipment configuration is often modelled in YANG and then consumed by a C northbound API. The API fills a C data structure that mirrors the YANG tree. This is straightforward for leaf nodes; it becomes tricky when the YANG model has lists, presence containers, and optional subtrees.

This PoC implements the `dhcpd` YANG model in C using [stb_ds](https://github.com/nothings/stb), a single-header C library for dynamic arrays and hash maps. The key constraint: embedded systems require known, bounded memory. All strings use fixed-length arrays rather than `char *`, so the struct sizes are deterministic at compile time.

The `dhcpd` module has a top-level `dhcp` container with two list subtrees: `subnets` and `shared-networks`. Each subnet has an optional `range` presence container. In YANG, a presence container has semantic meaning when absent — it is not just an organisational container. The C struct models this with a `has_range` boolean flag alongside the `DhcpRange` struct.

## Fixed strings vs char pointers

The `STRING_LENGTH_MAX 32` limit is a deliberate constraint. Every string field is `char[32]`. The `STRCPY` macro wraps `strncpy` with a `static_assert` that catches any attempt to copy into a buffer smaller than `STRING_LENGTH_MAX`. The assert fires at compile time, not at runtime.

An alternative implementation using `char *` and heap allocation is included as `dhcp_config.c.charptr`. On a system with a real allocator and no stack concerns, this is cleaner. On a deeply embedded target where you want the entire configuration in a single `malloc` — or no `malloc` at all — the fixed-length approach is necessary.

## Building

The Makefile downloads `stb_ds.h` from the upstream repository on first build if it is not present. No system-level installation needed:

```bash
make        # downloads stb_ds.h if missing, then compiles
./dhcp_config
```

The STB headers are designed to be vendored. Alternatively, pin to a specific commit in your project tree rather than downloading at build time.
